# 森夜 · 極簡數位底牌

線上網址：https://lrsjudge.netlify.app/

本地執行 `npm ci`、`npm start`，開啟 http://localhost:3000 。需要 Node.js 20+（Netlify 使用 Node.js 22）。

## 操作流程

1. 法官建立 6 / 9 / 12 人房，取得 **4 位數**房間碼。法官不佔座位。
2. 玩家輸入房號，自選實體座位，不需暱稱或帳號。
3. 最後一個座位入座時，伺服器立即隨機派牌。
4. 玩家頁為黑底全螢幕；持續按住底牌 350 毫秒顯示角色與一句技能提示。鬆手、滑出、觸控取消、切換頁面或視窗失焦立即遮蔽。亦支援持續按住空白鍵或 Enter。
5. 看過後可確認已了解，法官可看到確認狀態。法官僅有「重新發牌 / 解散房間」管理入口；重新發牌保留座位並重置确认狀態。

所有遊戲階段、技能、死亡與勝負均在線下主持，程式不再操作或結算這些流程。

## 手機與重連

線上版本直接開啟 https://lrsjudge.netlify.app/，手機可以使用不同網路。

本地版本需手機與電腦連同一 Wi-Fi，開啟 `http://電腦區域網路IP:3000`；防火牆需允許 TCP 3000。

座位憑證保存在同一瀏覽器的 LocalStorage，關閉後重開會自動恢復；也可重新輸入房號恢復。恢復不會重派或重複佔位。其他装置不能僅憑房號及座位冒領底牌。清除瀏覽資料或更換瀏覽器後，無法恢復原憑證，需由法官解散重建。

每 4 秒同步座位與重新發牌；頁面隱藏時暫停，返回時立即同步。短暫斷線仍可查看已收到的牌，重新連線後更新。關閉瀏覽器後的恢復需要伺服器可連線。

線上版本使用 Netlify Functions 與 Netlify Blobs：房間在不同請求與重新部署之間保留，最後一次入座、確認或重發後 24 小時過期。過期資料在讀取時失效，同一房號可被新房間重新使用。座位與派牌採強一致性讀取及版本條件寫入，避免並發選座覆蓋。解散使用版本化標記，避免已發出的請求重新建立房間。

本地 `npm start` 使用記憶體儲存，重啟仍會清除房間。應用面向可信任的線下聚會，尚未實作反濫用限流。

## Netlify 部署

GitHub 的 `main` 分支已連接 `lrsjudge` 站點。`netlify.toml` 設定發布 `public/`、打包 `netlify/functions/api.mjs`，並在構建時執行測試。API 路徑為 `/api/*`。Blobs 憑證由 Netlify 自動配置，不需在程式碼保存金鑰。

推送 `main` 即觸發部署。可執行 `npx netlify-cli build --offline` 驗證構建與函式打包。

## 驗證

`npm test`：涵蓋 6 / 9 / 12 人配置、座位競爭、自動派牌、身分隔離、憑證恢復、法官權限、重發及解散，以及長按卡片的遮蔽事件。另驗證多個函式實例同時入座、並發確認、過期房間和解散後的版本衝突。
